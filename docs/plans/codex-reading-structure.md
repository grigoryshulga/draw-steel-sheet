# Кодекс: Книга + Справочник

Дизайн читательской структуры Кодекса. Согласованное направление: разделить
«читать подряд» и «найти конкретное», вместо плоской копии оглавления печатной
книги. Документ описывает целевую структуру, маршруты, совместимость ссылок и
этапы. Контент (`content/rules/**`), ID статей и сущностей, паки и форматы
сохранённых героев не меняются — вся работа в манифесте навигации и UI.

## Принципы

1. **Навигация — данные, не код.** Части, секции справочника и маппинг
   «статья → класс+уровень» вычисляет сборка (`scripts/content/build-rules.mjs`)
   и кладёт в `src/generated/rules/manifest.json`. UI читает и не содержит
   главных номеров и редиректов.
2. **Одна страница — один канонический текст.** Справочник не создаёт вторых
   копий статей: те же статьи доступны из второй точки входа. Новые страницы
   появляются только там, где читательской единицы ещё нет (лендинг класса).
3. **Старые ссылки работают.** `#/codex/<id>` для всех 296 статей остаётся
   рабочим; ссылки на статьи-уровни классов превращаются в якоря лендингов.
4. **Поиск один, закладки одни.** Полный текст индексируется один раз; результат
   знает, куда вести (статья, якорь лендинга, каталог).

## Диагноз текущей компоновки

- 21 глава плоским списком = оглавление книги; нет иерархии и задач чтения.
- Главы 16/18/19 («Список Проектов/Сокровищ/Титулов») — каталоги: в
  `CodexView.tsx` хардкод `chapterCatalog()` по префиксам `"16."`, `"18."`,
  `"19."` отправляет их в `#/catalog`. Глава 06 «Список Карьер» при этом
  остаётся статьями. Четыре однотипные главы ведут себя по-разному.
- Глава 08 «Классы» = 100 статей «N-й Уровень X» (10 уровней × 10 классов);
  страницы класса нет, чтение о классе — прыжки по 10 статьям.
- Три входа (`#/codex`, `#/catalog`, `#/glossary`) со слайдером в шапке;
  глоссарий — статья `0102`, редиректящая в отдельный view.
- Главная — сетка 21 карточки без маршрутов «с чего начать».

## Целевая структура

Две вкладки «Библиотеки»: **Читать** и **Справочник**. Каталоги и глоссарий
перестают быть отдельными вкладками и становятся секциями Справочника.

### Читать — проза по частям книги

| Часть | Главы | Статей |
| --- | --- | --- |
| I. Как играть | 01 Введение · 02 Основы · 12 Тесты · 13 Ведение Боя · 14 Переговоры · 11 Нюансы | 53 |
| II. Создание героя | 03 Создание Героя · 04 Происхождения · 05 Предыстория · 07 Способности · Классы (обзор) · Комплекты (обзор) · Перки (обзор) | 41¹ |
| III. Между боями | 15 Проекты Отдыха · 17 Награды | 9 |
| IV. Ведущему | 20 Для Ведущего · 21 О Проекте | 12 |

¹ Статья `0701` «О Классах» числится дважды: в главе «Способности» и как
обзорная страница «Классы». Уникальных статей в части — 40.

Из дерева чтения уходят (содержимое доступно через Справочник):

- **06 Список Карьер** — 18 статей-карточек без прозы → секция «Карьеры».
- **08 Классы** — 100 статей-уровней → лендинги классов. В чтении остаётся
  обзорная страница «Классы»: текст статьи `0701` «О Классах» + сетка 10
  классов со ссылками на лендинги.
- **09 Комплекты** — в чтении `0901` «О Комплектах» и `0902` «Таблица
  Комплектов»; 22 статьи комплектов → секция «Комплекты».
- **10 Перки** — в чтении `1001` «О Перках»; 6 статей-типов (`1002`–`1007`,
  каждая — список перков) → секция «Перки».
- **16/18/19 Списки** — секции «Проекты», «Сокровища», «Титулы» (каталоги).

Глава 04 «Происхождения» остаётся в чтении целиком (порядок создания героя) и
продублирована входом в Справочнике — двойная точка входа, один текст.

### Справочник — сущности как точки входа

| Секция | Единиц | Источник |
| --- | --- | --- |
| Классы | 10 лендингов | агрегация: сущность `class.*` + `feature/class-*` + `ability/class-*` + статьи 08xx как секции-уровни |
| Происхождения | 14 | статьи `0402`–`0415` |
| Карьеры | 18 | статьи `0601`–`0618` |
| Комплекты | 22 | статьи `0903`–`0924` |
| Перки | 6 групп / 47 | статьи `1002`–`1007` (группы по типам) |
| Сокровища | каталог | `#/catalog/treasure` (источник — глава 18) |
| Титулы | каталог | `#/catalog/title` (источник — глава 19) |
| Проекты | каталог | `#/catalog/project` (источник — глава 16) |
| Глоссарий | термины | существующий `#/glossary` |

Лендинг Справочника — сетка секций с числами и краткими описаниями, тот же
стиль, что у главной «Читать». Секции-каталоги и глоссарий переиспользуют
существующие view внутри общей оболочки (шапка «Библиотеки», общий поиск).

## Лендинг класса

Единица чтения о классе — одна страница. Маршрут `#/reference/class/<slug>`
(slug — английский id класса: `fury`, `shadow`, …).

Состав страницы:

1. **Шапка**: имя, `originalName`, эпитет и Героический ресурс (из сущности
   `class.*`), арт класса.
2. **Обзор**: markdown сущности класса + абзац из `0701`.
3. **Подклассы**.
4. **Особенности**: сущности `feature/class-<slug>`, сворачиваемые группы.
5. **Способности**: сущности `ability/class-<slug>`, группировка по типу
   действия/уровню получения.
6. **Уровни 1–10**: каждая статья `08xx` — секция `<section id="level-N">` с
   внутренним оглавлением в существующем стиле «В этой статье».

Данные для агрегации уже есть: у каждого класса — сущность (`class.fury` и
т. д.), каталог особенностей и способностей по группам, 10 статей-уровней в
отдельном паке `chapter-08-<class>`. Лендинг собирается из одного паков,
без слияния статей в контенте.

### Совместимость ссылок и закладок

- `#/codex/08xx` → замена на `#/reference/class/<slug>#level-N`
  (порядковый номер статьи в группе = уровень).
- Закладки: формат не меняется (массив id в localStorage). Лендинг
  закладывается как `class.<slug>`; закладки уровневых статей ведут на якорь
  лендинга. `0102` больше не редиректится — Глоссарий открывается секцией
  Справочника, а статья остаётся статьёй.

## Манифест вместо хардкодов

`build-rules.mjs` дополняет `manifest.json`:

```jsonc
{
  "parts": [
    { "id": "how-to-play", "title": "Как играть",
      "chapters": ["01. Введение", "02. Основы", "12. Тесты", "..."] }
    // II. Создание героя, III. Между боями, IV. Ведущему
  ],
  "reference": [
    { "id": "classes", "title": "Классы", "kind": "classes" },
    { "id": "ancestries", "title": "Происхождения", "kind": "articles",
      "items": ["0402", "…"] },
    { "id": "careers", "title": "Карьеры", "kind": "articles", "items": ["0601", "…"] },
    { "id": "kits", "title": "Комплекты", "kind": "articles", "items": ["0903", "…"] },
    { "id": "perks", "title": "Перки", "kind": "articles", "items": ["1002", "…"] },
    { "id": "treasures", "title": "Сокровища", "kind": "catalog", "catalogKind": "treasure" },
    { "id": "titles", "title": "Титулы", "kind": "catalog", "catalogKind": "title" },
    { "id": "projects", "title": "Проекты", "kind": "catalog", "catalogKind": "project" },
    { "id": "glossary", "title": "Глоссарий", "kind": "glossary" }
  ],
  "classLandings": [
    { "classId": "class.fury", "slug": "fury", "name": "Неистовый",
      "levelArticleIds": ["0801", "…", "0810"],
      "featureGroup": "class-neistovyy", "abilityGroup": "class-neistovyy" }
  ]
}
```

Из `CodexView.tsx` удаляются `chapterCatalog()` и спец-обработка `0102`;
`src/rules/codex-navigation.ts` становится единственным читателем этой секции
манифеста. Оглавление статьи (headings) уже в манифесте — части и секции
ложатся в тот же механизм.

## Поиск и закладки

- Поисковый корпус один (уже ленивый `search.json`). Попадание в статью-уровень
  класса линкуется на якорь лендинга, а не на отдельную страницу.
- Фильтр «искать только в этой главе/части» остаётся; контекст части
  подставляется из манифеста.
- Закладки едины для «Читать» и «Справочника».

## Этапы

Каждый этап самостоятельно выкатываем и закрывается `npm run check`
(`content:check` входит туда) плюс ручная браузерная проверка навигации.

1. **Навигация из данных.** Манифест получает `parts`/`reference`/
   `classLandings`; сайдбар и главная «Читать» группируют главы по частям;
   вкладки «Библиотеки» становятся «Читать»/«Справочник»; хардкоды
   `chapterCatalog()` и редирект `0102` удаляются. Справочник пока показывает
   секции существующих каталогов/глоссария и списки статей.
2. **Лендинги классов.** Маршрут `#/reference/class/<slug>`, агрегация паков,
   секции-уровни с якорями, редиректы `#/codex/08xx`, поиск и закладки ведут
   на лендинг. Тест на маппинг «статья → класс+уровень» для всех 100 статей.
3. **Полировка чтения.** Обзорная страница «Классы» (0701 + сетка классов),
   вычитка состава частей, мобильная навигация двух вкладок, «пути читателя»
   на главной (новичок / создание героя / в бою / ведущему).

## Что не меняется

- Файлы `content/rules/**`, ID статей и сущностей, паки, `search.json`.
- Формат сохранённых героев и каталогные id (`consumer-identity.json`).
- Внутренности CatalogView/GlossaryView (они становятся секциями).
- Конвейер потребителей (`build-consumer-data.mjs`) — этап не трогает его.
