# Аудит производительности — 6 ноября 2026

Аудит выполнен относительно `691c092`. Исправления сокращают загрузку кода и данных; мгновенное открытие на любом устройстве не подтверждено браузерными измерениями.

## Найденные причины и изменения

- **Правила героя загружались даже при гостевом чтении.** `App` теперь содержит вход и ленивую границу `WorkspaceApp`. Гостевой Кодекс не импортирует управление персонажем. Отдельно исправлен импорт `CHARACTERISTICS` в `CatalogAction`: подписи читаются из лёгкого `rule-display`, без движка расчётов.
- **Журнал действий подтягивал каталог всех способностей в начальный граф.** `HistoryDialog` вынесен за ленивую границу рабочего пространства. Развитие, сведения о герое, инвентарь, журнал заметок и спутники также загружаются отдельно от основного листа.
- **Стоимость черт требовала полной проекции конструктора.** Генератор записывает `cost` непосредственно в проекцию особенностей. Адаптер листа больше не импортирует `builder.json`. Поведенческие тесты проверяют цену каждой канонической черты и отсутствие цены у знаковых черт. Формат сохранённых персонажей не меняется.
- **Чтение зависело от ответа хранилища персонажей.** В рабочем пространстве книга и справочник могут отображаться во время загрузки героя и при ошибке этой загрузки. Проверка авторизации остаётся в `AuthGate`.
- **Неизменившийся Markdown повторно разбирался при обновлениях родителей.** `RuleMarkdown` мемоизирован. Производные характеристики вычисляются при изменении персонажа, а не при каждом уведомлении или переключении раздела.
- **Локальный production-сервер передавал текстовые файлы без сжатия.** Сборка создаёт `.br` и `.gz`; сервер выбирает представление по `Accept-Encoding`, отдаёт `Vary`, `ETag` и `304`, поддерживает `HEAD`. Файлы передаются потоком вместо выделения полного буфера на каждый запрос. Ресурсы с хешем кешируются на год, HTML перепроверяется. Отсутствующие ресурсы по-прежнему возвращают `404`.

## Измерения сборки

Размер статического графа JavaScript каждой точки входа, включая транзитивные импорты; общие файлы внутри графа посчитаны один раз. Строки **нельзя складывать**: они пересекаются. Это не полный сетевой вес страницы и не измерение задержки. Не включены CSS, шрифты, изображения, API и динамически загружаемые статьи/поиск.

Сравнение выполнено на production-сборках без переменных Supabase, в одной рабочей копии и с одним lockfile. До изменений граф восстановлен по импортам сохранённых JS-файлов; после — по Vite manifest.

| Точка входа | До, KiB без сжатия | После, KiB без сжатия | Сокращение | После, KiB Brotli |
| --- | ---: | ---: | ---: | ---: |
| Начальная оболочка | 4705.7 | 256.0 | 94.6% | 75.2 |

Для локального API оболочка сразу догружает рабочее пространство; уменьшение оболочки не означает аналогичного сокращения всего открытия листа. При включённом Supabase оболочка составляет примерно 461.5 KiB без сжатия / 132.2 KiB gzip. Эта конфигурация проверена отдельной сборкой с фиктивными публичными параметрами, без обращения к облаку.

В опубликованном приложении используется Vercel: изменения Node static handler относятся к `npm start`. Они не доказывают дополнительный выигрыш от сжатия на Vercel; там доставкой и заголовками управляет платформа. Разделение JavaScript и устранение лишних зависимостей действует в обоих вариантах размещения.

## Защита от регрессий

`npm run check` выполняет архитектурные проверки, проверку актуальности генерации, тесты, TypeScript, production-сборку и `npm run perf:check`. Последняя команда обходит статический граф manifest и ограничивает размер оболочки, рабочего пространства, книги, справочника и листа. Лимиты учитывают SDK Supabase. Для отдельной сборки: `npm run perf:check -- путь/к/dist`.

HTTP-тесты проверяют сжатие и восстановление исходного тела, размеры передачи, выбор кодирования, кеширование, `304`, `HEAD`, SPA fallback, некорректные URL и обход пути. Общий прогон: 110 файлов, 1408 тестов.

## Оставшиеся ограничения

- Лист всё ещё загружает общие механики всех классов и крупные проекции. Следующий существенный шаг — пакеты по классу и асинхронный контракт загрузки перед расчётами; простая замена синхронных импортов здесь рискует нарушить расчёты сохранённых персонажей.
- Поиск уже загружается отдельно, но его корпус остаётся большим. Прежде чем вводить Web Worker или иной индекс, нужен профиль задержки ввода на слабом устройстве.
- Репозиторий правил уже кеширует загрузки пакетов и статей; иллюстрации используют `loading="lazy"`, `decoding="async"` и заданные размеры. Эти механизмы сохранены.
- Браузерные LCP/INP, переключение разделов на телефоне, реальная сеть и live Supabase не проверялись. Результаты тестов и размеры пакетов не заменяют эти проверки.

Главное изменение доставки: `loadRuleArticle` запрашивает отдельный хешированный JSON с выбранной статьёй и всеми её сущностями, включая ссылки в другие главы. Тесты сравнивают каждый из 296 файлов с полными исходными пакетами, включая английский текст. Прямые запросы сущностей по-прежнему могут загружать пакет главы. Если пакет уже загружается или закеширован (например, страница класса запрашивает агрегат и десять уровней), статьи используют его без дополнительных запросов.

Для холодного открытия одной статьи медианный размер её данных с Brotli уменьшился с **34 966 до 3 552 байт (−89.8%)**. Это медианы для всех 296 статей: до — соответствующий JS-пакет главы из production-сборки, после — отдельный JSON-ресурс. Общие JS/CSS, изображения и API не входят в эти числа. Примеры: «Основы» — 16 473 → 4 248 байт; «9-й уровень Элементалиста» — 48 144 → 3 872 байт. Сама оболочка приложения практически не изменилась.

Проверены HTTP-ответы всех 296 ресурсов из production-сборки: успешный статус, JSON MIME, точное содержимое, сжатие и immutable-кеширование. Репозиторий объединяет одновременные запросы и допускает повтор после ошибки; это покрыто отдельными тестами. Число файлов сборки увеличилось: размер репозитория и доставки всего сайта не является размером загрузки одной страницы.

Счётчик опыта теперь использует лёгкую функцию `levelUpProgress`. Полная проверка повышения уровня загружается только для доступного по опыту перехода или при открытии развития. Старые правила порога опыта, включая ручной порог и некорректные сохранённые значения, проверены тестами. Во время загрузки проверки кнопка временно отключена. Публичная библиотека начинает рендериться, пока Supabase проверяет сессию; приватный лист по-прежнему ждёт авторизации.

Лимиты JavaScript в `perf:check` ужесточены; добавлена проверка наличия отдельного JSON для каждой статьи и медианного размера не более 8 KiB gzip. Обычная сборка и сборка с фиктивной конфигурацией Supabase проходят эти лимиты. Итоговый набор: 115 файлов, 1434 теста. Браузерные LCP/INP и работа live Supabase по-прежнему не измерены; уменьшение байтов не означает такое же сокращение времени открытия.
