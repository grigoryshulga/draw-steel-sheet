# Происхождения: способности в листе

Дата: 2026-10-30.

## Зачем

Классовые особенности уже разложены на сгенерированный скелет и авторские
механики. Происхождения оставались исключением: конструктор показывал
карточки способностей только для восьми черт с таблицей броска силы и только
внутри выбора черты, а на листе этих способностей не было вовсе. Игрок видел
«у вас есть следующая знаковая способность» в тексте черты и вручную искал
карточку.

Теперь способности происхождения выводятся из выбранных черт и показываются в
общем блоке способностей наравне с классовыми, комплектными и базовыми:
действие, бросок, тиры, урон, поиск, фильтр «Происхождение» и кнопка
«Использовать» работают одинаково.

Архитектурный ориентир — [Forge Steel](https://github.com/andyaiken/forgesteel):
там происхождение — набор типизированных фич, а `getAbilities` собирает
`FeatureType.Ability` из всех источников героя, включая происхождение. Карточки
не хранятся отдельным списком выбранных способностей.

## Модель

### Скелет

`scripts/build-ancestry-features.mjs` читает `src/data/builder.generated.json` и
собирает `src/data/ancestry-features.generated.json`:

```ts
interface GeneratedAncestryFeature {
  id: string;              // ancestry.devil.glowing-eyes
  ancestryName: string;    // Дьявол
  kind: "signature" | "trait";
  name: string;
  cost?: number;           // только у купленных черт
  articleId: string;
  description: string;     // markdown источника
}
```

Правила ID:

- купленная черта — `ancestry.<происхождение>.<черта>`;
- знаковая черта — `ancestry.<происхождение>.signature.<черта>`;
- 11 ID числовых черт сохранены в прежнем виде (`ancestry.dwarf.grounded`),
  потому что они уже записаны в сохранённых листах и проверяются тестами;
- у способностей стабильные английские ID, как в справочнике способностей.

Скелет руками не правится: `npm run data:rules` пересобирает его после
`build-builder`.

### Механики

`src/data/ancestry-features/mechanics/abilities.ts` — авторские карточки
способностей, ключом по `id` записи скелета:

```ts
interface AncestryFeatureMechanics {
  abilities?: Ability[];
  choice?: {
    group: string;       // automation.ancestryFeatureSelections
    label: string;
    options: { id: string; label: string; ability: Ability }[];
  };
  effects?: FeatureEffect[]; // задел на перенос числовых эффектов
  notes?: string;
}
```

Сейчас покрыта 21 карточка: 19 способностей Forge Steel из базовых
происхождений плюс «Дать Волю» Тауруса и «Наследие драконов» Ящера из
перевода. Числовые эффекты
(скорость, выносливость, устойчивость, отход) остаются в старом реестре
`ANCESTRY_FEATURE_RULES`; его ID совпадают со скелетом, поэтому одна и та же
выбранная черта разрешается в обоих местах.

### Выбор способности

«Псионический дар» Рейдера Времени даёт одну из трёх способностей. Выбор
хранится в `automation.ancestryFeatureSelections`:

```json
{
  "ancestry.time-raider.psionic-gift":
    "ancestry.time-raider.psionic-gift.psionic-bolt"
}
```

- Конструктор пишет выбор в `draft.ancestryChoices` и требует его, если черта
  выбрана.
- Лист показывает селектор в блоке способностей; без выбора карточки нет,
  чтобы не показывать три взаимоисключающие способности одновременно.
- При смене происхождения выбор очищается в `recalculateCharacter`, как и
  старые `ancestryTraitIds`/`ancestryTraits`.

### Старые листы

До этого изменения билдер записывал в `automation.ancestryTraitIds` только
числовые черты. Поэтому `selectedAncestryFeatureIds` берёт канонические ID и
дополняет их названиями из `automation.ancestryTraits`: старый лист с
«Светящиеся глаза» получает карточку без миграции. Совсем старый ручной лист
без `automation` читает точный префикс `Название (стоимость):` из текста
`ancestryTraits`. Чужие и неизвестные ID игнорируются, а способности
показываются и при выключенном авторасчёте — авторасчёт отвечает за числа,
а не за состав правил.

## Проверки

- `tests/ancestry-features-skeleton.test.ts` — покрытие книги, уникальность и
  сохранение старых ID.
- `tests/ancestry-abilities.test.ts` — выдача знаковых и купленных
  способностей, выбор «Псионического дара», старые листы, фильтр, применение
  через журнал игры, сохранение и очистка выбора.
- `npx vitest run --testTimeout=60000`, `npm run build`, `git diff --check`.

## Ограничения

- Числовые и иммунные эффекты происхождений ещё не переехали в
  `AncestryFeatureMechanics.effects`; их считает старый реестр.
- Выборы вроде типа иммунитета Драконьего Рыцаря или руны Дварфа остаются
  текстом правил.
- Способности происхождения нельзя править или удалить на листе: они выданы
  чертой. Их можно применять и смотреть в полном окне.
