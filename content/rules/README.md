# Канонические правила

Дерево авторских файлов, из которого собирается доставка Кодекса. Исходные
`src/data/*.generated.json` пока остаются совместимыми входами для старых
потребителей и не удаляются.

## Структура

- `articles/<chapter>/<id>.json` — статья: метаданные и упорядоченные блоки
  `markdown` / `entity`.
- `entities/<kind>/<group>/<id>.json` — маленькая сущность с полным исходным
  Markdown, стабильным `id`, `legacyIds` и необязательной структурированной
  проекцией `ability`.
- `migration-report.json` — отчёт последнего импорта: покрытие, unmapped,
  composite-блоки, отложенные виды и оставшиеся потребители старых данных.

Физическое имя файла может санироваться, но идентичность всегда задаёт `id`
внутри JSON. Ссылки статьи указывают на `entities...id`; сборка отвергает
неразрешённые ссылки, повторяющиеся ID и повторяющиеся `legacyIds`.

## Команды

```bash
# Первый импорт из закоммиченных src/data/*.generated.json
node scripts/content/import-legacy.mjs

# Осознанная перезапись канонических файлов (ручные правки будут потеряны)
node scripts/content/import-legacy.mjs --replace

# Проверить импорт без записи
node scripts/content/import-legacy.mjs --dry-run

# Инкрементально добавить комплекты, сокровища, проекты, титулы и виды
node scripts/content/migrate-entities.mjs

# Проверить, нужна ли такая миграция (код выхода 1 — нужна)
node scripts/content/migrate-entities.mjs --check

# Детерминированная сборка доставки из content/rules
node scripts/content/build-rules.mjs

# Проверить, что src/generated/rules совпадает с каноническим деревом
node scripts/content/build-rules.mjs --check
```

Сборка читает **только** `content/rules/articles/**` и
`content/rules/entities/**`. Она пишет `src/generated/rules/manifest.json` и
ленивые пакеты `src/generated/rules/packs/<packId>.json`. Глава классов
делится по классам, остальные главы — по одной на главу.

## Что мигрировано точно

- 512/512 способностей: полный цитатный блок, `ability` — только проекция.
- 815/845 классовых особенностей: 578 обычных заголовков, 185 composite
  (внутри есть извлечённая способность), 52 ссылаются на ability-блок.
- 97/97 особенностей происхождений.
- 47/47 перков.
- 14/14 видов происхождений: вступление до первой черты; сами черты остаются
  отдельными `feature`.
- 21/22 комплектов: текст до знаковой способности; ссылки на способности
  сохраняются отдельными блоками.
- 100/100 сокровищ, 19/19 проектов отдыха и 59/59 титулов из статей глав
  16, 18 и 19.

30 синтетических строк таблиц («Растущая свирепость …: 2» и т.п.) не имеют
собственного блока и остаются прозой статьи; они перечислены в отчёте. Ещё 39
структурированных цитатных блоков вне старого набора способностей (встроенные
способности происхождений, сокровищ, титулов, статблоки) также остаются в
тексте статей и извлечённых сущностей и перечислены в
`unmapped.abilityLikeBlocks`.

## Отложено

Комплект «Буревестник» (0924) чередует несколько форм, прозу и блоки
способностей. Цельная сущность переставила бы правила, поэтому статья остаётся
как есть, а комплект перечислен в `deferred`. 13 структурированных блоков
внутри сокровищ, проектов и титулов остаются частью этих сущностей:
`RuleEntity` не поддерживает вложенные сущности. Это перечислено в
`stageTwo.unsupportedNested`, а не выдано за отдельную миграцию.
