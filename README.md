# Достать листы!

Интерактивный лист героя для настольной ролевой игры **Draw Steel**. Веб-сервис на React + TypeScript с локальным сервером: персонажи сохраняются на диск, в приложении доступны встроенные цветовые схемы.

Интерфейс полностью на русском. Названия способностей, состояний и навыков взяты из перевода [drawsteel-ru](https://github.com/grigoryshulga/drawsteel-ru); официальный лист MCDM использован как ориентир по составу полей.

## Разработка и качество

Границы модулей, правила параллельной работы агентов и оставшиеся ограничения описаны в [архитектуре](docs/ARCHITECTURE.md). После `npm ci` команда `npm run check` выполняет проверку импортов, тесты и production-сборку; тот же набор запускается в CI.

## Что умеет

- **Быстрый старт** — создание героя, импорт JSON и переход в Кодекс доступны с первого экрана. На телефоне основные разделы подписаны в нижней панели; настройки — кнопка-шестерёнка в верхней панели.
- **Надёжное автосохранение** — смена, копирование, импорт и удаление героя ждут записи текущих изменений. При ошибке доступны повтор и скачивание копии; закрытие страницы с несохранёнными правками вызывает предупреждение браузера. Это не полноценный офлайн-режим: аварийное закрытие может потерять правки в памяти.

- **Иллюстрации** — прозрачные PNG для 10 классов, 14 происхождений, 22 комплектов и 18 карьер. Арты показаны в конструкторе, Кодексе, выборе комплекта, инвентаре и на странице героя. Карточки используют лёгкие PNG-превью. Официальная основа и созданные с AI изображения различаются в кредитах; источники и промпты сохранены в [документации артов](docs/art/README.md).

- **Конструктор героя** — девять этапов по книге: замысел, происхождение с бюджетом черт, культура, карьера с перком и инцидентом, класс и подкласс, комплекты, способности, детали, проверка. Превью заполняется сразу; черновик сохраняется в браузере.
- **Кодекс правил** — весь существующий перевод: 296 статей, 21 глава, поиск по полному тексту, внутренние ссылки, таблицы, оглавление статьи и закладки. Доступен по `#/codex` без создания персонажа.
- **Настраиваемый лист** — свободное размещение блоков на сетке 10 px. Панели можно перемещать мышью, касанием или стрелками, менять их ширину и высоту, скрывать и сворачивать. Положение одного блока не сдвигает соседние. Раскладка сохраняется отдельно для каждого героя в этом браузере.
- **Авторасчёт** — характеристики используются в уроне и производных значениях; класс, уровень, эшелон, комплекты и числовые черты происхождения определяют выносливость, восстановления и движение. Два комплекта тактика не складывают одинаковые бонусы; профиль урона выбирается целиком. При смене комплекта заменяется его знаковая способность.
- **Лист героя** — характеристики (−5…+5), бонусы к тестам, пороги тиров, потенциал от высочайшей характеристики, отдельный блок здоровья с выносливостью, временной выносливостью, утомлением и восстановлениями. В блоке ресурсов героя — крупные счётчики ресурса класса и всплесков, жетоны героя. Название ресурса автоматически следует за классом, включая ручные листы.
- **Быстрые игровые действия** — способности можно применять прямо с листа: бросить цифровые 2d10 или внести физический бросок, увидеть результат, тир и урон, затем отдельно подтвердить списание стоимости и всплесков одной операцией. Переброс не тратит ресурсы; способности без броска тоже поддерживаются. Для текстовой стоимости есть дополнительное поле ресурса и ручное освобождение от стоимости. Здоровье и ресурсы показывают предпросмотр перед применением; последнее действие можно отменить, если затронутые значения не менялись.
- **Здоровье и история** — урон сначала поглощается временной выносливостью; доступны временная выносливость, исцеление, передышка, отдых и ручная коррекция. Передышка и отдых показывают все изменения до подтверждения. История относится к текущему открытию героя, очищается при перезагрузке или смене героя и не перезаписывает посторонние изменения.
- **Удобство на телефоне** — при ширине до 700 px здоровье, ресурс, состояния и история закреплены в быстрой панели; порядок листа начинается со здоровья, ресурсов и состояний, затем идут способности и характеристики. Мобильный порядок не меняет сохранённые координаты десктопной раскладки.
- **Каунтеры и состояния** — урон с поглощением временной выносливостью, передышка, отдых, девять состояний со спасбросками (d10 ≥ 6).
- **Броски силы** — 2d10 + характеристика, преимущества/помехи (включая двойные), бонусы, критическое попадание, журнал бросков.
- **Способности** (блок на листе; кнопка «Добавить способность» открывает каталог, базовые действия или создание своей) — группировка по типам действий, формы для своих способностей, предпочтительная характеристика, расчёт натуральных порогов 2d10 для тиров 1–3, три тира урона/эффектов, расчёт урона по текущим характеристикам, трата всплесков, интерактивный каталог способностей из классов и комплектов. Способности происхождения выдаются выбранными чертами и знаковыми чертами и показываются в том же списке с фильтром «Происхождение»; выбор из списка (например, «Псионический дар» Рейдера Времени) делается прямо на листе.
- **Инвентарь** — комплект, оружие, доспех, предметы, расходники, сокровища (лимит «трёх безопасно»), безделушки, титулы.
- **Герой** — навыки по группам, перки карьеры и класса, языки, культура, карьера, особенности.
- **Перки на листе** — слоты карьеры и класса с описаниями; собственные перки добавляются, редактируются и удаляются прямо на листе без ограничений по слотам и типам; дополнительные перки можно выбирать из каталога.
- **Проекты отдыха** — блок на странице заметок: цель, накопленные очки, прогресс-бар, завершение и быстрые +1/+5.
- **Перки** — выбор по правилам: один перк карьеры и классовые перки на 2/4/6/8/10 уровнях с фильтрами по доступным типам и полным описанием.
- **Комплекты** — каталог 22 комплектов с бонусами, снаряжением и знаковой способностью; выбранный комплект показывает снаряжение и бонусы на странице инвентаря.
- **Сохранение** — автосохранение на сервере, несколько персонажей, дублирование, экспорт/импорт JSON.
- **Цветовые схемы** — пять встроенных палитр с русскими названиями, проверенных на контрастность текста.

## Развёртывание на Vercel с аккаунтами

Для опубликованной версии персонажи хранятся в Supabase PostgreSQL, а вход и регистрация выполняются через Supabase Auth. Vercel собирает Vite-приложение как статический сайт; локальный Node-сервер и JSON-файлы остаются вариантом для разработки.

1. Создайте проект Supabase и включите Email в **Authentication → Providers**.
2. Выполните SQL из `supabase/migrations/202610230001_create_characters.sql` в Supabase SQL Editor. Таблица включает RLS: пользователи могут читать и менять только свои листы.
3. В **Authentication → URL Configuration** добавьте домен Vercel в Site URL и Redirect URLs. Для регистрации с подтверждением адреса настройте email-шаблон и SMTP в Supabase.
4. Импортируйте репозиторий в Vercel. В Environment Variables задайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` из настроек API проекта Supabase. Ключ publishable доступен в клиенте; `service_role` сюда добавлять нельзя.
5. Запустите деплой. Настройки сборки находятся в `vercel.json`.

Для локального запуска скопируйте `.env.example` в `.env.local` и заполните переменные. Если их нет, приложение использует существующий локальный API с сохранением в `data/characters`.

Режим разработки поднимает Vite внутри Node-сервера (HMR на том же порту). Для обычного запуска:

```bash
npm run build
npm start
```

Сервер слушает только `127.0.0.1` по умолчанию. Порт и каталог данных можно переопределить:

```bash
PORT=9000 DS_DATA_DIR=~/draw-steel-data npm start
```

## Данные

- Персонажи: `data/characters/<id>.json` (атомарная запись, версия схемы в документе).
- Экспорт/импорт: **Настройки** (шестерёнка в верхней панели) → «Данные». Импорт всегда создаёт нового персонажа с новым id.
- API: `GET /api/characters`, `GET/PUT/DELETE /api/characters/:id`, `GET /api/health`.

Новые герои из конструктора используют авторасчёт. Старые листы сохраняют ручной режим; включить расчёт можно на странице листа. Редактирование максимума выносливости, восстановлений и параметров движения записывает постоянную поправку к вычисленной базе. Изменение максимума не лечит героя. Выбор темы, черновик конструктора и закладки Кодекса хранятся в `localStorage`; игровые данные и поправки входят в JSON персонажа.

Лист — монолитная адаптивная плита (`SheetView.tsx`, `SheetLayout.css`): на широком экране две колонки (характеристики, здоровье, способности — слева; потенциал, развитие, ресурсы, состояния, навыки, перки — справа), при ширине плиты меньше 760 px блоки идут одной колонкой, боевые (здоровье, ресурсы, потенциал, состояния) выше способностей. Ширина считается по самой плите (container queries), а не по окну, поэтому раскладка не зависит от соотношения сторон. Блоки не двигаются и не меняют размер.

Конструктор создаёт героя **1-го уровня** и проверяет базовые выборы, навыки, бюджеты и наборы характеристик. Обязательные способности класса/подкласса выдаются автоматически. Уникальные ситуационные эффекты, изменения от нюансов, вложенные выборы черт происхождения и некоторые числовые бонусы классовых особенностей пока применяются по тексту правил и ручными поправками. Увеличения характеристик и новые выборы при повышении уровня также выполняются вручную. Раздел Призывателя в текущем переводе пуст, поэтому этот класс доступен через ручное заполнение.

## Цветовые схемы

В приложении есть пять встроенных схем: «Стальная ночь», «Тёплый костёр», «Лиловые сумерки», «Светлый пергамент» и «Синяя глубина». Схему можно быстро переключить в верхней панели или выбрать в сворачиваемом разделе «Внешний вид» в настройках. Выбор хранится в `localStorage`.

На листе используется уютная фэнтезийная атмосфера с тонким орнаментом и печатью-мечом. Декор адаптируется к выбранной встроенной теме и не меняет структуру листа. Официальная отметка совместимости Draw Steel и её источник описаны в [документации бренда](docs/brand.md).

## Структура

```
server/            Node-сервер: API, статика и хранилище
src/
  components/      оболочка, примитивы UI, иконки
  data/            классы, навыки, состояния, шаблоны, каталог способностей
  lib/             правила (броски, урон, производные), API, темы, утилиты
  state/           контекст листа
  views/           Лист, Инвентарь, Журнал, Герой, Кодекс, Настройки
  styles/          дизайн-токены и общие примитивы
tests/             Vitest: правила и сервер
scripts/           сборка каталога способностей из правил
```

## Каталог способностей

Каталог собран из переведённых правил скриптом:

```bash
npm run data
```

Скрипты читают соседний репозиторий `drawsteel-ru` и обновляют `src/data/abilities.generated.json` (512 способностей), `src/data/perks.generated.json` (47 перков и правила доступа) и `src/data/kits.generated.json` (22 комплекта). Скрипты не входят в рантайм — приложение использует только готовый JSON.

Там же собирается `src/data/ancestry-features.generated.json`: 14 происхождений, их знаковые и купленные черты. Способности и выборы происхождений живут отдельно в `src/data/ancestry-features/mechanics/` — по той же схеме, что механики классов: сгенерированный текст книги и авторские карточки с ключом по `id`.

Кодекс и данные конструктора также входят в `npm run data`. Их можно обновить отдельно:

```bash
npm run data:rules
# Другой каталог исходного перевода:
DS_RULES_DIR=/path/to/drawsteel-ru/vault npm run data:rules
```

Сборка сохраняет текст статей, преобразует Obsidian-ссылки и выноски в Markdown, исключает техническую главу `00. Оформление`. Пустые статьи остаются видимыми с пометкой. Два исходных файла с номером `0899` получают отдельные адреса `0899-9` и `0899-10`. Обычный запуск и `npm run build` используют готовые JSON и не требуют соседнего репозитория. Markdown выводится безопасным React-рендерером без исполнения HTML из источника.
